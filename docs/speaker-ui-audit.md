# 회의 코치 — 현재 기능과 UI/UX 점검

## 사용자 요구와 공급자 선택

주 사용 상황은 한 마이크로 여러 사람이 참여하는 대면 회의다. 내가 누구인지 지정하고, 내 발언 코칭·회의 맥락 질문·인사이트·중간 요약을 받아야 한다. 사용자는 Deepgram API를 사용하지 않기로 명시했다. 현재 전사와 코칭은 Gemini만 사용하며 다른 전사 SDK·연결·키 요구는 제거했다.

## 기능 상태

| 요구사항 | 현재 구현·검증 |
|---|---|
| 한 마이크의 자동 A/B/C 화자 구분 | **미지원**. Gemini Live 전사를 임의로 화자에 배정하지 않는다. 자동 구분 요구는 아직 충족되지 않았다. |
| 화자 지정과 내 화자 선택 | 음성 전사는 화자 미확인으로 표시. 사용자가 발언별로 A/B/C를 지정하고 내 화자를 선택한다. 기존 라벨은 보존한다. |
| 내 발언 코칭 | 선택한 화자의 발언만 COACH 근거로 허용. 실제 Gemini + 수동 화자 입력으로 확인했다. |
| 질문·인사이트 | 전체 회의 맥락을 사용하며 개인 코칭과 별도 필터로 표시. 실제 Gemini 호출에서 확인했다. |
| 중간 요약 | 현재 요약, 결정·액션·열린 질문, 이전 요약 타임라인. 저장·이전 결정 보존 테스트 통과. |
| 메모·회의록 | 원본 메모, 종료 후 초안·편집·확정·내보내기 유지. 전사 내보내기에 사용자가 지정한 화자 포함. |
| 반응형 UI | 데스크톱 전사/도움, 모바일 대화/도움/요약 직접 전환. shadcn Button/Input/Card/Tabs/Switch 사용. |

화자 선택만 하고 발언을 배정하지 않으면 개인 코칭의 근거가 없다. 다른 사람의 발언을 개인 코칭에 섞지 않기 위한 동작이다. 전체 회의 질문·인사이트·요약은 화자 미지정이어도 사용할 수 있다.

## 리서치·디자인 근거

공식 Impeccable 4.8.0의 context/init/Operate/craft-floor를 적용했다. https://github.com/pbakaus/impeccable/tree/main/plugin/skills/impeccable
독립 디자인 검토(A), 탐지기/브라우저 검토(B), 최종 검토·문서화를 수행했다. 탐지기는 한 번 실행했다. 기존의 큰 헤드라인/메모 우선 구조를 전사·도움 우선으로 바꿨으며 내 화자 선택, 근거 확인, 중간 요약을 바로 찾을 수 있게 했다.

데스크톱 1360×900, 모바일 390×844에서 넘침·키보드 탭/포커스를 확인했다. 수동 화자 선택 잘림, 스위치 히트 영역, 모바일 직접 탐색을 보완했다. 검토의 ship 판정은 해당 UI 수정 범위이며 자동 화자 구분의 인증이 아니다.

시각 체계는 DESIGN.md와 .impeccable/design.json, 제품 사실은 PRODUCT.md에 기록한다. 스크린샷의 대화는 명시된 검증용 임시 데이터다.

## 설정과 테스트

기존 Gemini/Supabase 환경변수 5개만 사용한다. 추가 전사 서비스 키를 입력할 필요가 없다. `.env.example`을 따른다.
`npm test`는 기존 큐/저장·로컬 정리·런타임 설정과 화자 미확인/개인 코칭 근거 제한/중간 요약 보존을 검증한다.
`tests/speaker_workspace.py`는 실제 Gemini와 수동 화자 입력을 사용하며 자동 음성 화자 분리를 검증하는 테스트가 아니다.

남은 공백: 자동 화자 분리, 긴 발화 중 즉각적인 코칭 지연, 장시간/겹침 발화 안정성, 직접 MCP 검색, 클라우드 동기화.
