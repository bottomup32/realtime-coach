# 실제 공급자·브라우저 음성 검증

## 검증 범위와 결과

이 테스트는 실제 Supabase 인증, 앱의 단기 토큰 API, Gemini Live WebSocket 및 코칭 API를 호출했다. AI 응답/전사/요약을 모킹하지 않았다. 개인 회의 녹음 대신 약 15.7초 길이의 합성 한국어 회의 발언을 사용했다.

| 항목 | 결과 | 근거 |
|---|---|---|
| 브라우저 마이크 → PCM → Live 전사 | 통과 | Chromium의 파일 기반 테스트 마이크, 실제 AudioWorklet, 한국어 출시/금요일 발언 확인 |
| 자동 요약과 코칭 | 통과 | 실제 서버 분석 200, 요약과 담당자 확인 카드 생성, 카드 근거 ID가 전사에 존재함 확인 |
| 종료·저장·재열기·내보내기 | 통과 | 회의록/원본 메모 보존, 새로고침 후 기록 다시 열기, Markdown 다운로드 |
| 발화 중 일시 정지 | 통과 | 발화 도중 중단 후 전사가 보존됐고 마이크 트랙이 ended로 전환 |
| 재시작·연결 종료 | 통과 | 같은 회의에서 재시작 후 WebSocket을 명시적으로 닫아 종료 처리·자원 해제·기록 보존 확인 |
| 마이크 권한 거절 | 통과 | 브라우저 권한 거절 후 메모 보존, 재시도 가능한 상태, 공급자 토큰 요청 없음 |
| 실제 다른 탭 오디오 | 통과 | 데스크톱 Chromium의 native getDisplayMedia, Tab audio/48kHz 트랙 확인. 마이크 입력은 무음이며 다른 탭의 합성 음성만 실제 Live에서 전사 |
| 공유 탭 종료 | 통과 | 공유한 탭을 닫으면 녹음 종료 상태로 돌아가고 회의록 생성 가능 |

다른 탭 테스트는 네이티브 탭 캡처를 사용하지만 물리 마이크 대신 AudioContext의 무음 스트림을 사용한다. 따라서 물리 장치와 탭 오디오의 동시 에코/음량 품질을 검증했다고 주장하지 않는다.

## 발견·보완한 사항

모델이 담당자 미정을 열린 질문에 기록하면서도 코칭 카드를 생략하는 경우가 있었다. 실행 일정에 합의한 뒤 담당자를 정하지 않고 다른 안건으로 넘어가는 경우를 명시적 코칭 기준으로 추가했다. 최근 카드도 다음 분석에 전달해 같은 질문의 의역 반복을 줄인다. 수정 후 실제 음성 재검증에서 질문 카드와 발언 근거를 확인했다. 소수 회 실행이며 모델 품질의 통계적 보장은 아니다.

가상 화면 입력을 사용하는 첫 탭 테스트는 음성을 전사하지 못했고, 헤드리스 native picker도 자동 진행되지 않았다. 데스크톱 디스플레이와 독립적인 오디오 소스 페이지로 변경해 실제 탭을 선택했고 통과했다. 가짜 화면 캡처 성공을 실제 상대방 오디오 캡처 성공으로 세지 않았다.

## 속도 해석과 남은 검증

- 전체 음성 흐름은 약 38초 내 완료됐다. 이 시간에는 4초 선행 무음, 약 15.7초 발언, 테스트의 의도적인 10초 대기 및 저장·재열기가 포함된다. 서비스 응답시간 수치가 아니다.
- 녹음 버튼부터 첫 저장된 전사까지 약 22.6~22.7초였다. 긴 발화 중 부분 전사가 계속 도착한 것이 아니라 발화 후 전사가 도착했다. 발화 중 코칭이 항상 즉시 나온다고 주장할 수 없다.
- 별도 앱 API 단독 확인에서는 서버 코칭 분석 약 1.1초였다. 음성 인식·전사 확정·클라이언트 대기를 포함하지 않는다.
- 발화 중 일시 정지 테스트는 중지부터 상태/저장 확인까지 약 1.4초였다.
- p95 2초 코칭/5초 요약 목표, 겹쳐 말하기·회의실 잡음·물리 마이크/스피커 에코, 30~60분 세션 및 모든 브라우저/OS는 미검증이다.
- 자동 세션 복원, MCP 직접 연결, 클라우드 동기화는 아직 구현되지 않았다.

## 재실행

실제 공급자 호출 비용과 익명 테스트 사용자 생성이 발생한다. 환경변수 5개와 Supabase anonymous sign-in이 필요하다. 키·세션·Live 토큰은 파일이나 로그로 출력하지 않는다. Node 24, Python Playwright, ffmpeg, `/usr/bin/chromium`을 사용한다.

```bash
# 이 환경에서는 Node의 프록시 지원을 명시적으로 켠다.
NODE_USE_ENV_PROXY=1 npm run dev -- --hostname 127.0.0.1 --port 3101

# 다른 터미널. TTS 모델 접근권한이 필요하다.
NODE_USE_ENV_PROXY=1 node tests/live/generate_audio.mjs
python tests/live/meeting_flow.py
python tests/live/lifecycle.py
python tests/live/permissions.py

# 데스크톱 디스플레이가 있는 환경. Linux 가상 디스플레이 사용 시 DISPLAY 지정.
python tests/live/tab_audio.py
```

생성된 오디오와 실패 스크린샷은 `/tmp`에만 저장한다. 실제 탭 테스트의 마이크는 무음이므로 별도 오디오 장치가 없어도 실행할 수 있다. Linux에서 디스플레이가 없다면 이 테스트를 통과 처리하지 말고 데스크톱 또는 Xvfb를 준비한다. 환경에 설치한 도구·테스트 파일은 사용자의 기존 브라우저 창을 제어하지 않는다.
