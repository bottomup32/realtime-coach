# 로컬 실행과 중첩 저장소 정리

이 제품은 회의를 듣고 기록하며, 현재 요약·필요한 확인 질문·이전 맥락을 제공하는 회의 코파일럿이다. 원본 메모와 회의록을 분리하고, 이전 노트를 다음 회의에 참고자료로 넣을 수 있다. 현재 기록은 브라우저에 저장된다. MCP 직접 검색·클라우드 동기화·자동 음성 연결 복원은 아직 없다.

## 녹음 버튼의 “Supabase 설정이 없습니다” 오류

이 오류는 Supabase 접속 실패와 다르다. 기존 코드가 브라우저의 빌드 시점 환경변수를 검사하다가 연결 시도 전에 중단하는 경우였다.
이제 브라우저는 `/api/coach/config`에서 실행 중인 서버의 공개 설정을 확인한다. 서버는 Supabase URL과 검증된 anon/publishable 키만 반환하며 Gemini 키·service_role/secret 키는 반환하지 않는다.
서버에 설정이 없다면 실행 폴더와 `.env.local`·서버 재시작을 안내한다. 잘못된 공개 키와 실제 익명 로그인 실패도 구분한다.

클라우드 환경에 입력한 값은 로컬 컴퓨터로 전달되지 않는다. 로컬의 실제 실행 폴더에 `.env.local`을 넣어야 한다. `.env.example`은 변수 이름을 알려주는 템플릿이며 실제 키를 입력·커밋하는 파일이 아니다.

## 순서

1. 실행 중인 개발 서버를 Ctrl+C로 중지한다. 중첩 폴더에서도 서버를 실행했다면 그것도 중지한다.
2. VS Code에서 바깥 `realtime-coach` 폴더를 연다. 터미널도 같은 폴더로 이동한다. 여기서 다시 `git clone`하지 않는다.
3. 로컬 수정 파일을 보존하면서 최신 코드를 가져온다. `git pull origin main`이 충돌을 보고하면 `reset --hard`나 강제 덮어쓰기를 하지 않는다.
4. 진단 명령을 실행한다.

```bash
npm run setup:check
```

출력의 `workingDirectory`가 실행할 폴더이고 `envFile`이 실제 `.env.local` 위치다. 변수 이름과 존재 여부만 출력하며 값은 출력하지 않는다. `missingNames`가 있으면 그 파일에 값을 입력한다.

5. 중첩 저장소가 있고 `safeToArchive: true`일 때만 아래 명령으로 정리한다.

```bash
npm run repo:tidy -- --apply
```

`realtime-coach/realtime-coach` 전체를 바깥의 형제 폴더 `realtime-coach-nested-backup-시간값`으로 옮긴다. 내부 `.git`, `.env.local`, 수정 파일, 추적되지 않은 파일, 설치 의존성을 모두 보존하며 삭제하지 않는다. 안쪽에만 있는 커밋도 Git 이력과 함께 보존한다. 바깥 `.env.local`은 덮어쓰지 않는다. 안쪽 환경파일만 사용해 왔다면 백업 파일을 확인해 필요한 값을 바깥 `.env.local`에 옮긴다.

동일 origin의 독립 checkout인지 확인되지 않거나 바깥 Git이 해당 경로를 추적 중이면 자동 이동을 거절한다. 다른 프로젝트·하위 모듈·링크된 worktree를 강제로 정리하지 않는다.

6. 바깥 폴더에서 실행한다.

```bash
npm ci
npm run dev
```

`.env.local` 수정 후에는 서버를 재시작한다. 프로덕션 실행 시에는 `npm run build` 후 `npm run start`를 사용한다. 브라우저에서 이전 서버·다른 포트의 탭을 보고 있지 않은지도 확인한다.

7. 회의 제목/목적 입력 → 녹음 시작 → 마이크 허용 → 발언 → 전사·요약·코칭 확인 → 종료·회의록 검토 순서로 시험한다. 원격 회의 상대방 오디오는 탭 공유에서 오디오 공유를 선택해야 한다.

Supabase에서 Anonymous Sign-In이 활성화돼 있어야 한다. 인증은 켰지만 화면이 계속 실패하면 오류 문구·실행 명령·접속 주소를 공유한다. 키 값이나 `.env.local` 내용은 공유하지 않는다.

## 회귀 검증

NEXT_PUBLIC_SUPABASE_URL/ANON_KEY 없이 프로덕션 빌드를 만든 뒤, 실행 시에만 실제 설정을 주입했다. 브라우저에서 런타임 설정 조회, 익명 인증, 녹음 시작, 합성 한국어 음성의 실제 Live 전사, 요약·코칭, 회의록 저장·재열기·내보내기까지 통과했다. 사용자 컴퓨터의 실행 폴더나 `.env.local` 값을 직접 확인한 결과는 아니다.

`npm test`는 기존 큐/저장 6개, 중첩 정리/보존 4개, 런타임 공개 설정/비밀 키 차단 2개를 실행한다. 테스트는 Node 24를 사용한다.
